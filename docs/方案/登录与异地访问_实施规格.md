# 登录与异地访问 · 实施规格（1.25）

> 状态：**已实施（1.25，2026-10-28）** —— 实现与实测结果见文末 §9；后续排期见
> [后续功能_技术方案.md](后续功能_技术方案.md)
> 目标：在"单机、无登录、数据只在本机"的现状上，补一层**可选的登录**与**安全的异地访问**能力，
> 不引入云数据库、不改变"数据留在本机"的承诺。
> 关联：[精简版改造_技术方案_1.22-1.25.md](精简版改造_技术方案_1.22-1.25.md) §6

---

## 1. 现状与风险

| 事实 | 风险 |
|---|---|
| 服务只监听 `127.0.0.1`（`server/server.js` 里 `server.listen(PORT, '127.0.0.1')`） | 手机/异地完全无法访问 |
| **没有任何登录**，任何能连上端口的人都能读写全部客户资料 | 一旦为了异地访问改成 `0.0.0.0`，等于把客户库裸奔在公网/局域网 |
| 会话、限流、审计都没有 | 被扫密码/爆破时无感知 |

**结论**：异地访问的前提是**先有登录**；"监听范围"必须与"是否设置密码"绑定。

---

## 2. 安全模型（先定边界）

1. **默认仍只监听本机**；异地访问是显式开启的能力，不是默认行为。
2. 启用异地访问的**前置条件**：已设置登录密码（否则拒绝切换监听范围，接口返回 400）。
3. 密码**只存 scrypt 加盐哈希**（`node:crypto` 内置），永不回传明文；重置密码需要本机操作（改设置项或删密码文件）。
4. 会话用**服务端签名 Cookie**（HttpOnly、SameSite=Lax、默认 30 天），密钥随机生成后持久化到数据库/文件，重启不掉线。
5. 防爆破：同一 IP 连续 5 次失败锁 15 分钟；锁定与失败写审计日志。
6. 审计：登录成功/失败/退出/改密/监听范围变更，记录时间、IP、User-Agent、结果。
7. 可选 IP 白名单（默认空 = 不限制；填 `100.64.0.0/10` 即只允许 Tailscale 网段）。
8. 不做：云同步、多租户、公网数据库、无密码监听 `0.0.0.0`、把密码写入日志。

## 3. 数据与配置（不新增表，全部走 settings）

| key | 含义 | 默认 |
|---|---|---|
| `auth_enabled` | 是否启用登录（开启后所有 API 需会话） | `0` |
| `auth_user` | 登录用户名（默认 `admin`） | `admin` |
| `auth_pass_hash` | scrypt 哈希（`scrypt$N$r$p$salt$hash` 格式，salt/hash 为 hex） | 空 |
| `auth_session_secret` | 会话签名密钥（32 字节 hex，首次启用时生成） | 空 |
| `auth_fail_state` | 防爆破状态（**按 IP 存一个 JSON**：`{"1.2.3.4":{"n":3,"until":1234567890}}`，until 为 epoch 秒） | `{}` |
| `listen_mode` | `local` / `lan` / `all` | `local` |
| `auth_ip_allow` | IP/CIDR 白名单，逗号分隔，空=不限制 | 空 |
| `auth_totp_secret` | 预留（本版不做二次验证） | 空 |

> 监听范围变更后需要重启服务（`server.listen` 绑定地址不可热改）；接口返回 `restart_required: true`，
> 前端提示"请关闭窗口重新启动"。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `GET /api/auth/status` | 是否启用登录、当前会话是否已登录、用户名、监听范围、是否可异地访问、最近登录 IP/时间 |
| `POST /api/auth/login` | `{ username, password }` → 成功下发 Cookie；失败 401 并累计次数；锁定返回 423 |
| `POST /api/auth/logout` | 清 Cookie，写审计 |
| `POST /api/auth/password` | 需已登录 + 旧密码；改密后**所有旧会话失效**（换 secret） |
| `PUT /api/settings` 扩展 | 增加 `listen_mode`、`auth_ip_allow`、`auth_user`；切 `lan/all` 且未设密码 → 400 |
| 中间件 | `auth_enabled=1` 时，除 `/api/auth/*`、`/api/health` 与静态 `login.html` 外，一律校验会话；未登录 401 |

**前端**：
- 新增 `web/login.html`（独立的极简登录页：标题、用户名、密码、错误提示、记住我 30 天），登录成功跳 `index.html`。
- `index.html` 加载时先 `GET /api/auth/status`：未登录且启用登录 → `location.replace('/login.html')`。
- 顶栏右上加"退出登录"；设置页加「登录与异地访问」面板（设密码/改密码、监听范围三档、IP 白名单、最近登录记录、Tailscale 操作指引）。

## 5. 异地访问的三种免费方案（写进设置页帮助）

| 方案 | 费用 | 手机侧 | 何时选它 |
|---|---|---|---|
| **A. Tailscale**（推荐） | 0 元（免费版最多 6 用户、设备不限） | 装 Tailscale App，访问 `http://100.x.x.x:8899` | 不想买域名、要最安全（不开公网端口） |
| **B. Cloudflare Tunnel** | 0 元 + 域名 10~30 元/年 | 浏览器直接开 `https://crm.你的域名` | 想发个链接就能在微信里打开 |
| **C. 公网 IPv6 + DDNS** | 0 元 | 手机需支持 IPv6 | 宽带有公网 IPv6、不想装客户端 |

每档都附一段 5 步操作指引（安装 → 登录同一账号 → 软件设密码并选监听范围 → 拿地址 → 手机打开）。
**共同前提**：先设密码；A/C 方案建议把 IP 白名单填成 `100.64.0.0/10`（Tailscale 网段）。

## 7. 验收标准（新增 8 项）

1. 默认未启用登录时，行为与 1.24 完全一致（只听 `127.0.0.1`、无需登录）；关闭登录后回到该状态。
2. 未设置密码时，切换监听范围为「局域网/全部」被拒绝，并说明原因。
3. 设置密码后可登录；错误密码 5 次锁定 15 分钟（提示剩余时间）。
4. 会话 30 天有效、刷新不掉线；退出后访问受保护接口返回 401。
5. 修改密码后旧会话全部失效，需重新登录。
6. 审计日志含登录成功/失败/退出/改密/监听范围变更，含 IP 与时间，**不含密码**。
7. 监听范围为「局域网/全部」时，服务确实在本机网卡上可访问（测试用同机 127.0.0.1 与出口 IP 双地址验证）；改回「仅本机」后需重启生效。
8. IP 白名单生效：不在白名单的请求 403，且不泄漏"密码是否正确"。

## 8. 风险与回退

| 风险 | 对策 |
|---|---|
| 忘记密码 | 本机可重置：停止服务 → 设置项 `auth_enabled=0`（或删除 `auth_pass_hash`）→ 重启，再用新密码 |
| 会话密钥丢失 | 仅导致需重新登录，不影响数据 |
| 监听 `0.0.0.0` 后局域网有人扫描 | 必须已设密码 + 5 次锁定 + 可配白名单；启动日志醒目提示 |
| 未来加 TOTP | 设置项 `auth_totp_secret` 已预留，不改表 |

> 一句话：**登录是可选的、默认关闭的；异地访问是"登录 + 监听范围 + 隧道"三件套，缺一不可。**

### 9.4 与规格的差异 / 安全取舍

1. **失败状态合并**：规格初稿写 `auth_failed_count` + `auth_locked_until` 两项，实现合并为一个
   `auth_fail_state` JSON（按 IP 存 `{n, until}`），少一项设置且天然支持多来源 IP。
2. **无状态会话**：Cookie 是服务端 HMAC 签名，不建会话表（符合"不新增表"）。因此**退出登录只清本机
   Cookie**；要让所有设备立即掉线，请改密码（轮换密钥）。这是为"零新增表 + 30 天免登录"做的取舍。
3. **首次设置密码限本机**：`POST /api/auth/password` 在还没有密码时只接受 `127.0.0.1` / `::1`
   的请求；已有密码时必须"已登录 + 旧密码"。避免开放局域网后被远程抢设密码。
4. **敏感设置双向拦截**：`auth_pass_hash` / `auth_session_secret` / `auth_fail_state` /
   `auth_totp_secret` 既不允许 `PUT /api/settings` 写入，也不会被 `GET /api/settings`、
   `GET /api/status`、`GET /api/auth/status` 回传。
5. **白名单范围**：对所有 `/api/*` 生效（`/api/health` 除外，保证启动器 / 单实例探测可用）；
   静态文件不拦，登录页仍能打开并显示 403 原因。
6. **启用登录的前置条件**：规格只写了"切监听范围要先有密码"，实现额外要求"启用登录也必须先有密码"
   （否则会把自己锁在门外），并保留启动时安全网：库里被直接改成非 local 但没密码，强制退回本机监听。
7. **未做**：TOTP 二次验证（仅预留 `auth_totp_secret`）、多用户/角色、只读模式、HTTPS 终止
   （由 Tailscale / Cloudflare 隧道负责）；密码强度只校验长度 ≥ 6，未强制复杂度。
