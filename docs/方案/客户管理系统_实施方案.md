## 1. 技术方案（零依赖 · 完全离线）

| 层 | 选型 | 说明 |
|---|---|---|
| 运行时 | Node.js v24.21.0（本机已具备） | 无需安装额外环境 |
| 数据库 | SQLite 单文件，使用 Node 内置 `node:sqlite` | **无需 npm install、无需编译原生模块** |
| 后端 | Node 内置 `http` 模块 + 自写轻量路由 | 不引入 express 等框架，永不因依赖升级损坏 |
| 前端 | Vue 3 全局构建版（本地 vendor 目录） + 原生 CSS | 零构建步骤，改完刷新浏览器即生效 |
| Excel | SheetJS 单文件版（本地 vendor 目录） | 仅开发时下载一次，运行时不联网 |
| 启动 | `启动.bat` / `停止.bat` | 重复双击只打开页面，不会启动第二个进程 |

**为什么不用云数据库（结论记录）**：本方案已用「本地 + 双份自动备份」覆盖数据安全需求，同时获得秒级响应、断网可用、零月费、零凭据泄露风险的收益。数据访问层做了隔离封装，将来若需要多设备访问，改动范围有限。

## 2. 数据库设计（17 张表）

通用约定：所有表含 `id`（自增主键）、`created_at`、`updated_at`；需软删除的表含 `deleted_at`（为空表示未删除）。

### 2.1 `customers` 客户主表（**v1.9 起：27 列 / 表单 4 区块 17 项**）

> **1.23 客户系统简洁化**：按决策 E，旧 8 区块 60 余字段全部删除，只保留客户本身必需的信息；
> 项目、回款、成本不再放客户表，而是由 1:1 项目档案（§2.5）与成本台账承载。
> 表单只有「资料 / 地址 / 主联系人 / 回访与备注」4 个区块，一屏 2 列放得下。

**② 地址**

| 字段 | 类型 | 说明 |

| 指标 | 公式 |
|---|---|

## 5. 关键业务规则

1. **自动回填**：保存跟进记录 → 更新客户 `last_follow_at`、`follow_count`、`next_follow_at`；若设了下次时间用它，否则按客户 `follow_cycle_days` 自动排下次；若设了下次时间 → 自动生成一条待办
2. **自动算钱**：新增/修改/删除实收流水 → 实时刷新项目 `received_amount` 与 `payment_status`；客户财务汇总（已收/应收/毛利/毛利率）实时派生，不存冗余成交额
3. **自动待办**：回款计划创建时 → 按提醒天数自动生成待办
4. **查重**：新建客户时若「名称相同」或「主联系人手机相同」→ 弹窗提示并展示已有记录
5. **软删除**：客户/项目/跟进/待办删除进回收站；回收站 30 天后自动清理（可设置）
6. **日志**：所有写操作记录摘要 + 变更前后值
7. **备份**：每天首次启动自动备份一次，`backups\` 保留最近 30 份，`backups\mirror\` 保留最近 7 份（第二份副本，防误删与硬盘故障）
8. **表单校验**：客户名称必填；合同金额与回款金额 ≥ 0 且为数字；计划收款日必填；实收金额不得超过欠款（超出时警告但允许，标记为「超收」）

## 6. 启动与日常使用

- **首次**：双击 `启动.bat` → 自动检测 Node → 建库建表 → 启动服务 → 打开浏览器 `http://127.0.0.1:8899`
- **日常**：双击 `启动.bat` 即可（已在运行则只打开页面）；关闭黑窗口或双击 `停止.bat` 结束

## 9. 客户分布统计与收入报表（1.22 起取代地图）

### 9.1 为什么改

地图（离线 GeoJSON + 坐标转换 + 在线核对入口）在个人自用场景里价值有限：客户集中在新疆几个地州，
真正想看的是"各地州各多少家""哪个行业客户多""今年赚了多少"，而不是地理形状。
1.22 按使用者要求**直接删掉地图模块**，换成**两张环形图 + 一张收入报表**，同时把成本记账补上，让"利润"能算出来。

### 9.2 分布统计

| 维度 | 口径 | 界面 |
|---|---|---|
| 地区 | 按客户 `region_name`（地州）聚合，Top 8 + "其他"；空值归「未归属」 | 首页环形图，可切换维度 |
| 行业 | 按客户 `industry` 聚合 | 首页环形图（默认第二张） |
| 来源 | 按客户 `source` 聚合 | 环形图下拉切换 |
| 标签 | 按 customer_tags 聚合，未打标签单独成组 | 环形图下拉切换 |

- 接口：`GET /api/stats/distribution?by=region|industry|source|tag&top=8`
- "地址 → 地州"归属逻辑保留（原在地图模块里，现搬到客户服务），行政区划改为本地种子
  （`server/data/region.json`，121 条），**全新安装也离线可用**
- 点扇区可跳转到按该条件筛选的客户列表（1.22 只做跳转，具体筛选在客户页）

### 9.3 收入报表与利润

| 指标 | 口径 |
|---|---|
| 收入 | `payments` 中 `type='实收'` 的金额，按 `actual_date` 归月/归年 |
| 采购成本 | `costs` 分类=采购成本，按 `spent_at` 归月/归年 |
| 维护成本 / 差旅 / 其他 | 同上，按分类 |
| **利润** | **收入 − 采购成本 − 维护成本 − 差旅 − 其他** |
| 毛利率 | 利润 ÷ 收入（收入为 0 显示 —） |
| 应收未收 | Σ(回款计划 − 已核销实收)，只算大于 0 的 |

- 接口：`GET /api/stats/income?by=month&year=YYYY`、`?by=year&span=5`、`GET /api/stats/income/detail?month=YYYY-MM|year=YYYY`
- 首页 v2 一次请求拿全：`GET /api/dashboard/v2?month=YYYY-MM`（指标卡 + 回访提醒 + 待办 + 动态 + 两张分布）
- 成本在客户详情「成本台账」登记，可挂客户与项目（只给项目时自动带出客户）；全部软删除、写审计日志

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 硬盘损坏 / 误删 data 目录 | 数据全失 | 双份自动备份到不同文件夹；建议定期把 `backups\` 拷到移动硬盘 |
| 端口 8899 被占用 | 无法启动 | 启动脚本自动探测并顺延端口，同时用记事本打开配置项供手工修改 |
| 浏览器缓存旧页面 | 改了功能看不到 | 静态资源加版本号参数，启动时自动刷新 |
| 附件占用空间过大 | 磁盘紧张 | 设置单文件上限（默认 50MB），界面显示已用空间 |
| 误操作改错数据 | 数据不准 | 操作日志可追溯 + 回收站可还原 |
| 单机无法多端访问 | 手机上看不了 | 现阶段不需要；数据层已隔离，将来可平滑扩展 |
| **采集合规风险** | 法律风险 | 不适用：1.21 起软件**不含任何采集/爬虫功能**（原招标采集模块已整体移除） |
| **成本记不全导致利润失真** | 报表不准 | 首页与设置页写明"利润 = 收入 − 全部成本"；成本台账分类登记，报表可下钻对账 |
