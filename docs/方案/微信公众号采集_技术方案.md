# 微信公众号内容采集 · 技术方案

> 状态：**方案已确认，W1 + W2 已实施**（1.19 发布）
> 已确认的决策：内置「粘贴链接 + RSS 订阅」两条路径；公众号转 RSS 那一步**暂时只用粘贴链接**；
> 口径「新疆 + 项目类词」；限速 3 秒 / 每轮 30 篇 / 每日 200 篇；资讯类收下并标注「资讯」。
> 目标：让「招标采集」模块除了读订阅邮件，还能**把与新疆项目有关的公众号文章收进来**
> 关联文档：[客户管理系统_实施方案.md](客户管理系统_实施方案.md)（§7.4 采集模块 8 项验收）、
> [后续功能_技术方案.md](后续功能_技术方案.md)（§1.2 已记的采集设计约定）

---

## 0. 先说结论（一句话）

**公众号文章的"正文"好抓，"文章列表"不好抓。**
所以本方案把重心放在"**用可靠的方式发现文章**"上：内置两条稳妥路径
（**粘贴链接** + **订阅 RSS**），把"公众号转 RSS"这一步交给外部服务（可选、不进主程序），
**不做**直爬搜狗、不做客户端 hook —— 既守住"零依赖、默认关闭、不抓网站"的既有承诺，
又能覆盖"凡新疆项目信息都收"。

## 1. 现状核实（已读代码，结论如下）

| 能力 | 现状 | 对本方案的意义 |
|---|---|---|
| 来源类型白名单 | `collect_sources.type` 仅允许 `subscription`（`service.js` 的 `ALLOWED_SOURCE_TYPES`），其余类型**手工写入也拒绝执行** | 新增"公众号/RSS"来源必须显式扩展白名单 —— 这是刻意的安全设计，保留 |
| 来源配置 | `config_json` 存 provider/host/port/user/mailbox/keywords/regionOnly/sinceDays | 新类型复用同一张表与同一套凭据规范（密码类字段只回"是否已配置"） |
| 暂存与审核 | `collect_staging` + `reviewStaging()`：**人工审核后才写入项目库**，带去重键与内容指纹（`noticeKey` / `contentHash`） | 公众号抓来的东西**一律先进暂存区**，不会污染项目库 —— 这是最重要的安全阀 |
| 新疆口径 | `extract.js` 已有 `XINJIANG_REGIONS`（地州/简称）、`isXinjiang()`（命中地州→是；只有"新疆"且无外省→是；同时出现外省→排除） | **"只要新疆"这一条已经实现**，本方案直接复用，不用重写 |
| 字段抽取 | `pickProjectName/pickAmount/pickRegion/pickDates/pickOrganizations/pickIndustry`，`detectPersonalInfo` 自动识别并脱敏个人信息 | 文章类内容的抽取可复用，命中率低于招标公告（见 §5 的降噪设计） |
| 邮件解析 | `mail.js` 已有 MIME/HTML→文本、编码解码、正文清洗 | 公众号正文抽取可复用其中的 HTML→文本能力 |
| 零依赖约束 | 后端只用 Node 内置模块；无 `npm install` | **没有现成的 RSS/HTML 解析库可用** → 需要自己写轻量解析（见 §4.2），这是本方案主要的技术工作量 |
| 联网承诺 | 只有一个联网模块（招标采集），**默认关闭、关闭时零请求** | 新增能力必须沿用：默认关闭、显式开启、可见的开关与日志 |

## 2. 现实可行路径（调研结论）

### 2.1 关键事实：难点在"发现"，不在"抓取"

- **文章正文**：`https://mp.weixin.qq.com/s?__biz=...&mid=...&idx=...&sn=...` 是**公开页面**，
  无需登录即可访问，正文在 `id="js_content"` 容器里 → 单篇抓取技术上很简单、风险低。
- **文章列表**：公众号**没有**面向个人的公开列表接口。
  「我怎么知道这个号今天发了什么」才是真正的问题，而各条路都有代价：

| 方案 | 可行性 | 代价 / 风险 | 结论 |
|---|---|---|---|
| **粘贴链接**（人工发现） | 完全可行 | 要人工，但零风险、零依赖、立刻能用 | ✅ **内置** |
| **订阅 RSS/Atom**（读标准订阅源） | 完全可行 | 需要"有人把公众号转成 RSS"；换来的是标准协议、稳定、可增量 | ✅ **内置** |
| **自建公众号转 RSS**（`wewe-rss` 等，基于微信读书） | 别人已做好，可私有化部署 | 要另跑一个服务（Docker/npm）、要扫码登录、账号有风控风险 —— 与"零依赖"冲突 | ⚠️ **外置**：只写指引，不做进主程序 |
| **直爬搜狗微信搜索** | 技术上能做 | 验证码 + Cookie 风控 + IP 限流，**随时失效**，要维护代理池 | ❌ 不做 |
| **公众平台素材接口** | 官方接口 | 只能读**自己运营**的号 | ❌ 不适用 |
| **微信 PC 客户端 hook / 本地缓存** | 能做 | 违反微信服务协议、有封号风险 | ❌ **坚决不做** |

> 调研到的可选项（供你判断"外置那一步"用哪种）：
> [wewe-rss](https://github.com/cooderl/wewe-rss)（基于微信读书，私有化部署，用得最多）、
> [we-mp-rss](https://github.com/DavidLam-oss/we-mp-rss)、
> [mprss](https://github.com/wechat-article/mprss)、
> [wechat-download-api](https://github.com/tmwgsicp/wechat-download-api)（作者已在讨论"新方案路径"，
> 说明这条路本身也在变）；[RSSHub](https://github.com/DIYgod/RSSHub) 的公众号路由依赖新榜 token（付费）。
> **共同点**：都需要额外的运行环境与账号态 —— 这正是它们不该进主程序的原因。

### 2.2 与既有"离线承诺"的关系

现在的承诺是"**不抓取任何网站，只读你订阅的邮件**"。
引入公众号后承诺需要**精确改写**为：

> 采集模块仍然只做两件事：① 读你订阅的邮件（IMAP，只读、不改邮箱状态）；
> ② 读你订阅的 RSS 源、以及**你主动粘贴的文章链接**。
> 不做全站爬取、不做搜索接口逆向、不使用他人 Cookie。
> **关闭时仍然零请求**；每一篇抓取都有日志、有频率限制、有每日上限。

这条改写必须在 README 与方案文档里同步更新（不能悄悄放宽）。

## 3. 推荐方案（W1 + W2 + W3）

### W1 · 粘贴链接采集（人工发现，零风险）

- 新增「**粘贴链接采集**」入口（采集暂存页右上角，也可在来源页建一个"链接收集"来源）
- 支持**一次粘贴多条**（每行一条），自动识别公众号链接格式
- 对每条：抓正文 → 抽取字段 → 地域判定 → 进暂存区（`pending`）
- 抓不到（文章已删/需要验证）→ 明确提示哪几条失败、为什么，成功的照常入库
- 复用：`mail.js` 的 HTML→文本、`extract.js` 的抽取与新疆判定

### W2 · RSS/Atom 订阅来源（半自动，主路径）

- 新增来源类型 `rss`（扩展 `ALLOWED_SOURCE_TYPES`），配置项：
  `名称 / 订阅地址 / 关键词 / 地域模式 / 每次最多取几篇 / 是否只取最近 N 天`
- 轮询：沿用现有"每 24 小时一次 + 有更新才动"的调度（可单独设频率）
- 增量：用文章链接 + 标题指纹去重（复用 `noticeKey` / `contentHash`），已收过的整条跳过
- **RSS 只管发现**：拿到链接后按 W1 的同一条流水线抓正文（有些源直接给全文，则直接用）

### W3 · 公众号转 RSS 的外部做法（只写文档，不做进程序）

在方案与软件内提供一段**指引**（不是自动安装）：

1. 用 `wewe-rss` 之类工具（自己电脑上另跑一个服务）把你关心的公众号转成 RSS；
2. 把那个 RSS 地址填进 W2 的"订阅地址"；
3. 本软件照常只读 RSS。

明确写出：这一步涉及**微信读书扫码登录 / 非公开接口**，属于使用者自选动作，
软件不内置、也不代管你的账号凭据。

### 3.1 关于"有关于新疆项目的信息均抓取"

现有订阅源是"关键词 + 只要新疆"两条一起用。公众号内容形态不同（资讯多、公告少），
所以新增**地域优先**口径，三档可选：

| 档位 | 收什么 | 适用 |
|---|---|---|
| `region`（宽松） | 命中新疆地州/县市/兵团师市 → 收 | 怕漏（你说的"均抓取"） |
| `region+project`（推荐默认） | 命中新疆 **且** 命中项目类词（项目/工程/采购/招标/中标/EPC/装置/管线/改造/扩建/阀门/管道/仪表…） | 降噪，避免"新疆某厂检修"之类无关资讯淹没暂存区 |
| `keyword`（严格） | 原来的关键词订阅 | 原有行为不变 |

再叠加**打分**（复用已有 `match_score`）：新疆命中 + 项目词命中 + 抽到结构化字段
（项目名/金额/招标人/日期）各计分 → 暂存区可按分数排序/过滤，**一眼先看高分的**。

"资讯"与"公告"的区分：`notice_type` 写「**资讯**」（公告类仍写招标公告/中标结果等）——
**不动表结构**，暂存区列表按此加一个标签即可。

## 4. 数据与接口

### 4.1 数据库

**建议不动表结构**（本方案的取舍）：

- 来源类型：`collect_sources.type = 'rss'`（已有列，只是扩展白名单）
- 来源配置：沿用 `config_json`（新增 `url` / `filterMode` / `maxPerRun` 等键）
- 文章信息：标题→`title`、链接→`source_url`、公众号名→`source_platform`
  （如"微信公众号 · 新疆招标网"）、摘要→`raw_excerpt`、类型→`notice_type`
- 其余（去重键、指纹、个人隐私、客户匹配、审核状态）**全部复用**

> 如果你希望把「公众号名」单独成列、以及新增「内容形态（资讯/公告）」列，
> 那就需要一次迁移（`v7 → v8`）。**建议先不做**：能不加列就不加，用现有字段足够；
> 真要加，等用一段时间后按实际需要再加更准。（若确认要加，A2 的迁移顺延为 v9。）

### 4.2 需要自己写的两个小轮子（零依赖的代价）

| 轮子 | 说明 | 难点 |
|---|---|---|
| **RSS/Atom 解析** | 取 `<item>` / `<entry>`，读 title/link/pubDate/description/content:encoded，处理 CDATA 与实体 | 没有 XML 库；用受控正则 + 实体解码即可，但**畸形 feed 要有明确报错**，不能静默丢数据 |
| **HTML 正文抽取** | 取 `id="js_content"` 容器 → 平衡配对找到结束标签 → 剥标签、解实体、保留段落换行 | 标签配对要自己写（不能用正则硬切）；复用 `mail.js` 的 HTML→文本 |

HTTP 用内置 `https`：手动处理重定向、UA、超时、**每篇间隔 ≥3 秒**、失败重试 1 次。

### 4.3 接口（草案）

| 接口 | 说明 |
|---|---|
| `POST /api/collect/wechat/paste` | 粘贴链接采集：`{ urls: [...], sourceId? }` → 返回每条的成功/失败与暂存区 id |
| `POST /api/collect/wechat/preview` | 只抓取与抽取、不入库（先看看能抽到什么） |
| 现有 `/api/collect/sources` | 扩展：支持 `type='rss'` 的字段与校验 |
| 现有 `/api/collect/staging`、`/review` | 不变（审核流程完全复用） |

### 4.4 界面

- **采集暂存**页：右上角加「**粘贴链接采集**」按钮（弹抽屉：多行文本框 + 抓取结果清单）；
  列表里给"资讯"加标签、显示来源公众号、支持按分数过滤/排序
- **采集来源**页：新增来源时可选类型「订阅邮件 / RSS 订阅」；RSS 的表单字段更简单
  （名称 / 地址 / 地域模式 / 关键词 / 每次上限）
- **采集记录**页：不变（每次抓取都写日志：抓了几条、几条命中新疆、几条进暂存、失败原因）
- 顶部保留"**采集总开关**"（默认关闭，关闭时零请求），并在开关旁写明当前会联网的场景

## 5. 降噪与容量（"均抓取"不等于"全塞进来"）

公众号一天可能几十篇，全收会淹没暂存区。方案里做四件事：

1. **两段判定**：地域命中（必需）+ 项目类词命中（默认必需，可关）→ 先砍掉明显无关的
2. **打分排序**：`match_score` 按命中项打分，暂存区默认按分数倒序
3. **每日上限 + 每轮上限**（可配，建议每轮 30 篇、每日 200 篇），超限记日志并停止
4. **批量操作**：一次勾选多条批量忽略/批量入库（现有审核流程已支持批量，直接复用）

## 6. 难点与风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 文章页风控 | 高频访问会出现"环境异常"验证页 | 单篇间隔 ≥3 秒、每日上限；命中验证页**立即停止本轮并提示**，绝不硬闯 |
| RSS 源不稳定 | 第三方源随时可能挂 | 解析/网络失败写明确日志；失败连续 N 次自动降级并在来源上标红（复用现有 `fail_streak`） |
| 文章≠公告 | 公众号多是资讯，字段抽取命中率天然低 | 用「资讯」标注区分；抽不到的字段留空，不硬猜；靠打分让高价值内容浮上来 |
| 合规边界 | 抓取公开页 vs 绕过限制 | 只抓公开可访问页面；不绕登录、不用他人 Cookie、不做客户端 hook；外置那一步的风险明确写进文档 |
| 离线承诺被误解 | 用户以为"还是完全不联网" | README 与设置页同步改写联网说明（§2.2 那段） |
| 零依赖解析器出错 | 自写解析器对畸形输入可能出错 | 解析器单独成模块 + 专门的测试套件（用本地模拟 RSS 服务器，与现有 mock IMAP 同思路） |
| 来源凭据 | RSS 地址可能带 token | 沿用现有凭据规范：只回"是否已配置"，日志脱敏 |

## 8. 验收标准（建议新增 R1~R4，与既有 31+8 项并行有效）

| # | 验收项 | 判定标准 |
|---|---|---|
| **R1** | 粘贴链接采集 | 单条与多条粘贴都能抓；抽到的字段正确进暂存区；**未审核不入项目库**；个别链接失败要指出是哪条、为什么 |
| **R2** | RSS 订阅 | 能订阅一个 RSS/Atom 源；只取新增、重复不重收；解析失败有明确提示；连续失败自动降级标红 |
| **R3** | 地域口径 | 凡命中新疆地市/县市/兵团师市即收；纯外省文章不收；「资讯」与公告类在暂存区可区分；打分排序可用 |
| **R4** | 礼帽与安全 | **关闭时零请求**；单篇间隔与每轮/每日上限生效；命中验证码页立即停止并提示；个人信息照旧脱敏；日志不含凭据 |
